# HarmonyOS 上的 QEMU/KVM 实测

结论：2026-10-23 在当前鸿蒙 ARM64 主机上，已使用 Harmonybrew QEMU 11.1.2 的 TCG
启动 Alpine Linux 6.12.114-0-virt，并在该 Linux 内通过 KVM 执行第二层 AArch64 指令。
这修正了先前仅因宿主没有 /dev/kvm 就认为没有本地验证路径的过早判断。
三种产品沙箱尚未因此被判定为安装成功，软件模拟数据不可用于正式性能横向选型。

实际安装：brew install qemu，来源 harmonybrew/core 的 arm64_ohos bottle。
包元数据 SHA256：054ea28b93fa0f29ffcaaca707cb341c1801a5fec7f917f9b1d9fb8645a2299e。
安装过程同时安装/更新了所需 brew 依赖。二进制实测列出 tcg/kvm/nitro；
这仅是编译支持，宿主 KVM 可用性不由这个列表证明。

Linux kernel/initramfs/config 下载自：
https://dl-cdn.alpinelinux.org/alpine/v3.22/releases/aarch64/netboot/
配置 CONFIG_KVM=y，测得文件摘要见 qemu-sha256.json（记录本次输入，不声称独立签名认证）。

启动参数：

```sh
qemu-system-aarch64 -machine virt,virtualization=on,gic-version=3 \
  -cpu max -accel tcg -m 768M -smp 2 -display none -monitor none \
  -serial file:kvm-smoke-serial.log -nic none \
  -kernel vmlinuz-virt -initrd probe-initramfs.gz \
  -append 'console=ttyAMA0 rdinit=/probe-init'
```

本次最多90秒限时，正常完成并主动 poweroff，退出0；不配置网卡、不映射宿主目录。
probe-initramfs 在原 Alpine initramfs 后附加 gzip/newc 归档，含 kvm-smoke 和 probe-init；
后者用 /bin/busybox 挂载 devtmpfs，运行探针并打印返回码，最后 poweroff -f。
探针在客体内部执行，不在鸿蒙宿主打开 KVM。静态 AArch64 Linux ELF 使用本地
OHOS SDK clang --target=aarch64-linux-gnu -nostdlib -static 编译，仅调用 Linux syscalls，
UAPI 结构取自 SDK 的 linux/kvm.h；不链接鸿蒙 libc。

实际输出（完整串口日志在同目录 qemu-kvm-smoke-serial.log）：

```text
PASS KVM_API_VERSION=12
PASS CREATE_VM
PASS VCPU_INIT
PASS KVM_RUN: L2 executed store(42), KVM_EXIT_MMIO
KVM_PROBE_EXIT=0
```

探针源码在 qemu-kvm-smoke.c：创建 VM、注册4KiB guest RAM、创建并初始化vCPU、
设定 PC/PSTATE、执行 KVM_RUN，验证实际 MMIO 写入地址、长度和值42。
这比“看到 /dev/kvm”或内核初始化成功更强，但不是完整 guest OS/产品兼容性测试。
下一步可在该 Linux 内逐一部署 ARM64 沙箱并验证1个实例，记录缺失设备/依赖；
不将本次探针成功替代三种沙箱的创建、删除、快照等验收。

技术依据：[QEMU virt 虚拟化扩展文档](https://www.qemu.org/docs/master/system/arm/virt.html)。
