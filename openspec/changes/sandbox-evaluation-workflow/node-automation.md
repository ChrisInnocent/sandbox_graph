# 工作节点脚本化职责与实现状态

2026-10-21，设计草案。本文是所有工作节点的职责索引；内部步骤与分支见 [node-workflows.md](node-workflows.md)，测量语义见 [test-nodes.md](test-nodes.md)，全局拓扑见 [design.md](design.md)。不修改执行代码，不代表已有可运行的 LangGraph 或统一测试系统。

## 1. 如何读“脚本化”

| 标记 | 含义 | 当前状态 |
|---|---|---|
| S | 目标上由确定性程序、脚本、调度器或渲染器完成；规则固定后不需要模型推理 | 本表所有统一节点均为 planned，未完成端到端验收 |
| M | 需要模型理解自然语言、审计语义、诊断未知异常或撰写证据约束的解释 | 结果为有来源的提案／解释，不覆盖原始事实 |
| H | 必要的人类输入、意图、授权范围或业务取舍 | 仅在已有记录不能解决时触发；不是逐节点常规批准 |
| 未脚本化 | 必须继续标注原因：语义判断、业务决策、缺规则、缺适配或只有草稿 | “缺规则／缺适配”不等于永久无法脚本化 |

S 是**应当脚本化的职责**，不是完成声明。实现状态独立使用 `planned / draft / implemented_unverified / locally_verified / environment_verified`，最后一种必须限定产品、环境、方法和版本。现有官方脚本是复用候选，不自动提升统一节点状态。

脚本合同 ID 是逻辑能力名称，不是已存在文件或可执行命令。后续可将多个合同放在同一工具内，或一个合同调用多个适配器；不得为凑表而逐行创建脚本文件。纯规则节点不调用模型；每个工作节点仍有负责 agent，看护以事件驱动，不是持续模型轮询。

## 2. 每个节点都要有的合同

| 字段 | 明确内容 |
|---|---|
| 身份与责任 | node_id、所属主图／环境组／工作实例、owner、图／合同／脚本版本、输入摘要 |
| S/M/H 分工 | 确定性子步骤、模型输入与输出 schema、人工触发原因；没有 M/H 时明确写“无常规参与” |
| 输入与输出 | 必填输入、证据引用及访问范围、版本、产物清单、校验规则、状态更新的拥有者 |
| 效果与预算 | read_only / local_write / external_mutation、资源所有权、并发锁、截止、日志／采样／模型预算 |
| 执行与恢复 | operation_id、attempt_id、幂等／对账接口、外部任务身份、检查点、失败分类和清理责任 |
| 判定与状态 | 执行成功、断言结果、数据有效性、复核、性能阈值、清理分别记录；进程退出零不等于全部通过 |
| 实现证据 | implementation_status、代码引用、验证范围与证据；不能只填一个“已自动化”布尔值 |
| 内部图 | node-workflows 中对应子图；公共机制继承 GATE，具体业务步骤不可省成一个“执行脚本”黑箱 |

建议脚本返回统一的 `node_result`：身份／输入版本、执行分类、断言列表、产物引用及完整性、外部资源／任务、指标可用性、重试或人工输入原因。错误分类至少覆盖缺输入、合同冲突、能力缺口、执行失败、超时未知副作用、采集缺失和清理失败；各类都有具体 affected_nodes，不停止无关分支。

脚本确定的阈值、归一化、重复去重、状态转移和覆盖核对不得由模型自由改写。模型提出修复时先产出结构化建议，脚本再检查输入、影响和既有授权；需要新取舍才交人工。临时生成的 shell 文本不能直接作为已核验执行合同。

所有节点继承 GATE：核验输入→对账／复用→执行→输出检查→保留证据→持久交付；异常先保存事实，涉及副作用先对账再有限重试。外部变化、未知副作用或过期锁不得仅靠 checkpoint 重放。wait 节点持久化事件游标与等待原因；人未回复不能当作批准。

模型诊断／人工等待前，脚本处理发压、采样器、既定撤压／故障恢复及资源保留，登记所有者、期限和到期处置；未知副作用隔离冲突域。缺合同、缺适配不能直接继续；C1 的新模型方案需有相应可执行适配及验证证据才交 C2。

## 6. 每个场景方法的脚本化边界

下表所有测量动作均为 S/planned；M 仅处理方法语义、未知适配或证据解释，不能直接替代测量；H 仅处理未确定的业务条件。各模板内部流程图按 B/E 编号一一列在 node-workflows，变体用分支体现。

| 用例模板／N05 方法 | S：可脚本化的核心 | M／H：未脚本化边界 |
|---|---|---|
| B01.TEMPLATE、B01.SNAPSHOT | 源核验、唯一提交、状态／日志观察、所选计时、独立功能后验 | M核验状态／日志语义；H决定主完成点和后验覆盖 |

| E04.PRESSURE | 已确认压力阶梯、业务正确性、撤压和恢复核验 | M解释压力机制；H对象、强度和范围 |
| E05.INTERFERENCE | 配对基线／干扰窗口、共置核验、退化计算及解除 | M解释因果限制；H负载、隔离策略 |
| E06.RECOVERY | 已确认故障注入、事件计时、恢复、任务丢失／重复检查 | M提出诊断假设；H故障范围与恢复目标 |

S 的范围还包括状态观察频率、日志解析和关联去重、PSS完整覆盖、CPU峰值先聚合再求最大、实际 cohort 分母、不同时间域检查、冷态／预热证明、缺采样状态、列表完整性、TTL 续租、迟到创建对账。未定义参数或未适配实现应报告 blocked/insufficient，不转而让模型猜数。

所有密度创建阶段同步产出1秒成功创建速率曲线，以及实际发起／接纳速率、整轮吞吐、失败与迟到。计数按所选终点、唯一操作身份及观察时间，缺测不填零，最终存活数与累计创建成功数分开。统计由 N08/A3 脚本完成，不额外开启逐秒模型节点。零实例增量方法在 N04 取得基线后才由 N05 创建待测 cohort，N02/N03 仅准备来源及预检复位。
