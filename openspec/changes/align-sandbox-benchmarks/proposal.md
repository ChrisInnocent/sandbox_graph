# Proposal

> 实施继续暂停。本文按最新需求同步节点职责与测量合同，不授权恢复提前产生的代码。统一依据为 [职责表](../sandbox-evaluation-workflow/node-automation.md)、[节点内部图](../sandbox-evaluation-workflow/node-workflows.md) 和 [场景合同](../sandbox-evaluation-workflow/test-nodes.md)。

## Why

AgentENV、CubeSandbox 与 Kuasar 的创建完成事件、密度计算和生命周期测试口径不同，直接比较仓库脚本的数字会产生错误结论。本 change 将源码审计、方法交叉适配和执行证据分开，落实已有选型工作流中的统一测试合同。

## What Changes

- 审计当前检出的三套源码及测试脚本，逐项映射 B01 至 B10，记录版本、计时边界、能力差异及未覆盖项。
- 在 `sandbox_graph` 增加独立的统一测试层，复用产品接口，不修改沙箱生命周期实现。
- 创建分列 API 返回、状态就绪、经核验的内部日志耗时及可选命令完成，支持异步等待；命令不强制计入创建耗时。
- 三个候选都支持执行逐批扩容测量和固定实例资源外推两类密度方法；原脚本口径保留可追溯的复现视图，统一口径单独标识。
- 区分实例列表数量、命令可执行数量、资源估算容量与实测条件容量；保存负载、规格、预算、停止原因及清理结果。
- 本地合同测试与真实沙箱测试分别报告；缺少环境、模板或凭据时保持实际运行未完成，不以模拟数据充当性能结果。
- 密度增加固定请求预算下的滑窗／分批不同并发对比，同步采集每秒创建吞吐、各角色／组件 PSS、CPU 时间与峰值，并使用同窗口真实 cohort 计算平均开销。

以下工作均目标脚本化，当前统一执行链尚未验收：R1/T0 的版本与引用检查；N00–N03 的合同、对账、fixture 与预检；N04–N06 的采集、发压、观察和后验；N07–N10 的封存、计算、清理与交付；A1–A7/F1–F4 的确定性计算、事实装配与校验。逐节点 S/M/H 和内部流程见上述索引；模型保留新语义分析、未知异常诊断与报告解释，人工只决定未明确条件／范围。不能将本 proposal 或官方脚本视为实现完成证据。

## Capabilities

### New Capabilities

- `cross-sandbox-benchmarking`：跨沙箱基准的源码证据、方法合同、创建就绪测量、密度交叉适配与运行证据。

### Modified Capabilities

无。`sandbox-evaluation-workflow` 是尚未归档的总体需求，本 change 只实现其中的跨产品测量适配，不代表完整图引擎已交付。

## Impact

- 新增根目录测试工具、自动化测试、无凭据配置示例与源码审计文档。
- 以本地检出的版本为证据，不宣称等同于远端最新版本；不覆盖各嵌套仓库已有改动。
- 实测需要用户环境组的 API、数据面及宿主资源采集入口、指定规格模板或镜像、执行范围和凭据引用。

最新实施入口统一为 [sandbox-evaluation-workflow/tasks.md](../sandbox-evaluation-workflow/tasks.md) 15–26 组及对应执行／契约设计；本目录旧9项不并行派发，也不因新计划已制定而勾选旧实现完成。
